HarmonyOS arm64 + OPS pilot — run report (null result, submitted for the record)

WHAT THIS IS
An offline, budgeted ops-ga search run executed on a HarmonyOS PC (MNT-W72C, aarch64,
HongMeng Kernel 1.13.0) against a dsh-ops ("OPS") plugin ported to openharmony-arm64.
Two attempts were run inside one user-approved CNY 20 total budget. Neither attempt reached
the repository's export bar (a measured holdout token improvement), so nothing is exported
and no OPS/DSH source or profile changed. The package below is attempt 2.

SANDBOX (IMPORTANT)
  This host cannot enforce any DSH sandbox: no bubblewrap, and the Landlock launcher probe
  dies with SIGSYS (exit 159), so workspace-write/read-only fail closed at the first confined
  call. The runs therefore used permission=danger-full-access inside an isolated home and
  temp workspaces. That mode is REACHABLE ONLY WITH AN EXPLICIT ACKNOWLEDGMENT in the local
  copy of the framework (runner.acknowledgeUnenforcedSandbox + runner.sandboxEvidence, plus
  tests); the upstream default still refuses it. Every evaluation record, receipt, lane state,
  candidate.json, final result and the export artifact of these runs carries
  sandboxEnforced=false plus the measured evidence string. This is a platform limitation, not
  a claim that full access is safe, and it is why the numbers below are a pilot, not a score.

FINDINGS
  1. src/runner.mjs propose() still disables the ids dsh-ops, ops-file, ops-shell, ops-ptc,
     ops-discovery, ops-sdk. dsh-ops 0.3.1 mounts dsh-ops-shell, dsh-ops-file, dsh-ops-ptc,
     dsh-ops-tui, and the patch loader SILENTLY IGNORES unknown ids (verified: booting with
     all six unknown ids prints no warning and exits 0). So during optimizer proposals the OPS
     tools are not hidden, contrary to the comment "Disable them, not merely ask the agent".
     A follow-up fix should use the real component ids, or make an unknown id an error.
  2. A winner selected on a two-task tuning gate by a 5% token margin inverted to +43% tokens
     on the held-out test (attempt 1). This matches the framework's own honesty flag
     statisticalNonInferiorityProven=false; a small gate is not a reliable selector, so the
     gate (or elites) should grow before any guidance change is trusted.
  3. The framework cannot run at all on hosts without a Landlock/bwrap backend; it needs the
     explicit, recorded exception described above (local only in these runs).

  node bin/ops-ga.mjs run      --config <config> --lane operations --allow-paid
  node bin/ops-ga.mjs validate --config <config> --lane operations --allow-paid
  node bin/ops-ga.mjs export   --config <config> --lane operations --out <file>   # refuses: no improvement
  The private config differs from config.redacted.json only in the redacted paths and in the
  sandbox-acknowledgment fields described above; the search/task/price fields are identical.

LIMITS
